#### vox-lab 主要开发者
语音处理多推理运行时实验，覆盖语音识别（ASR）、音源分离、TTS（语音合成），横向实测 Burn、ort、GGML、PyTorch 在 CPU / Vulkan / ROCm 等设备上的推理表现。
项目业绩：
1.
音源分离选型：同一 htdemucs 模型横比 tch(CPU) 1.03 / Burn-wgpu 2.41 / 基于上游 WGSL 实现的 Vulkan 路径 0.11（约 9×），说明瓶颈在通用栈的 kernel 实现而非核显本身
2.
TTS 后端：Radeon 780M上 Burn/CubeCL 无 bf16 matmul 支持，改用 f16 后端绕过，Vulkan RTF 3.9–5.6，优于 PyTorch CPU；并用 PyTorch 参考逐段验证精度（VAE 编码 29.40 dB、特征编码 42.76 dB）。
3.
LM 解码数值对齐：
现象：Rust 实现与 PyTorch 的 LM（自回归主干）解码最初只对上 1.97 dB。
定位：逐张量对照，先确认是两侧 CFM 初始噪声来自不同随机流（差异被 pred_feat 回灌放大），两侧都固定噪声后一致到 27–40 dB，证明 LM 实现本身与参考一致。随后发现同一二进制进程间可复现，但不同构建之间预填充结果不同（该阶段不经过采样，无随机源，权重与输入相同）；排除进程级非确定性、精度（bf16 同样复现）、autotune 缓存三种解释后，判断为 cubecl 在 Vulkan 上的 kernel 选择差异。
4.
推理链路确定性：Burn 未暴露种子，自己生成 N(0,1) 再灌入，为 CFM 初始噪声与 VAE NoiseBlock 注入可复现 seed（手写 Box–Muller 对齐分布），使同一文本在同一构建下可复现。
5.
分段耗时分析：用 forward hook 按叶子模块归组，量化 base_lm 36.2% / CFM 29.6% / VAE 13.6% / encoder 9.4%，并识别出 44.6% 的时间落在模块之外的 Python 胶水与 KV cache 管理上。
