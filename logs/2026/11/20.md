**压力例子 A——GPU 卡死（三个模型全遇到，VoxCPM 没真正解决）**：

背景：在 780M（gfx1103，ROCm）上跑语音链路，**几乎每个模型在 GPU 上都卡死/崩溃过**：

| 模型 | GPU 上的现象 |
|---|---|
| Whisper | openai-whisper + ROCm 25 次子进程试验 0 通过，连 39M 的 tiny 也立刻崩；whisper.cpp 的 HIPBLAS 构建跑 170s 长音频卡死；faster-whisper 开 word_timestamps 触发 GPU watchdog |
| Demucs | PyTorch htdemucs（shifts=3）GPU 卡死 |
| VoxCPM | PyTorch from_pretrained GPU segfault；ONNX 的 Dawn WebGPU 内存泄漏、MIGraphX 慢 10× |

压力点：**一旦 GPU 卡死，整张显卡进入降级状态，连其他进程的 GPU 操作
也会连锁卡住**——上一个 trial 的失败会污染下一个，测出来的数根本不可信。

复盘与定位：先排除「是不是模型本身不行」——不是。
- whisper.cpp 同一份源码换后端完全不同：Vulkan 构建稳定（RTF 0.081），
  只有 HIPBLAS 构建在长音频上卡 → 问题在**特定后端**，不在模型、不在硬件。
- demucs 是另一条线，不是"换后端"而是"换运行时"：
  通用推理框架 Burn（wgpu）上 RTF 2.41（跑不动），
  换成针对 HTDemucs 手写的专用推理运行时
  （上游 WGSL 实现，conv/attention/STFT/overlap-add 全自研，
  不依赖 libtorch/ROCm）走 Vulkan，RTF 0.11，约 9×。
  同一份模型换实现差近 10 倍 → **瓶颈在通用栈的 kernel 实现，
  不是模型、也不是核显本身；针对模型定制推理运行时才能跑满**。

**卡死/崩溃的一部分原因是算子缺失，不全是随机 hang**：
- VoxCPM：`cubek-matmul` 直接 panic `BF16 lhs/rhs/output not supported`
  ——gfx1103 没有 bf16 matmul，`Cube` 策略直接 panic 而非回退。
- Demucs：rocBLAS 缺 gfx1103 的 Tensile 内核、conv 走回退 solver。
这属于"算子/内核缺失"，和随机 GPU hang 是同类但不同的问题。

解决（两条线分开）：
1. **实验方法**：改成每个 trial 用全新子进程，识别退出码
   （SIGSEGV -11 / SIGABRT -6 / 超时）——这是为了**隔离污染、让测量可信**，
   不是"修好了卡死"。
2. **实际绕开分"完全绕开"和"部分绕开"**（按模型分别处理）：
   - Whisper → **换 GGML 推理引擎**（whisper.cpp 的 Vulkan 构建，
     模型 `ggml-large-v3-turbo`，RTF 0.081 稳定）；另一条线是
     faster-whisper（CTranslate2）GPU + CPU int8 兜底 → 完全绕开 ✅
   - Demucs → 走基于上游 WGSL 的 Vulkan 路径 → 完全绕开 ✅
   - VoxCPM 的三条路正好是分层例子：
     - 换 f16 → Vulkan RTF 3.9–5.6，稳定可用 = **完全绕开**，
       但有精度代价（VAE 编码 29.40 dB vs f32 90.35 dB）
     - 强制朴素 matmul → bf16 能跑通，但 RTF 76.58（慢 18×）
       = **部分绕开**，只是证明"数值链路本身没问题"，无实用价值
     - 等驱动暴露 bf16（VK_KHR_shader_bfloat16）→ 本机不支持，**没绕开**
   - 最终 VoxCPM 在业务链路上退回 CPU（RTF 6.6、weights ~4.7GB），
     这是唯一没彻底解决的。

**依据**：`common.cn.md:106` 失败路径记录 +
`vox-lab/packages/research/model-load-benchmarks.md:53-72` +
`vox-lab/docs/research/whisper/README.md:18-52` +
`vox-lab/docs/research/voxcpm/burn-gpu-backends.md:14-60`。
**注意（别讲反）**：
- 独立子进程是**隔离污染、保证测量可信**的实验方法，不是解决卡死的手段。
- 卡死有随机 hang 和算子缺失两类原因；算子缺失可以靠换精度/朴素实现绕开，
  但朴素实现只是"部分绕开"（能跑但没用）。
- 三个模型不是一种解法：Whisper/Demucs 完全绕开，VoxCPM 只有 f16 部分可用、
  业务上仍回 CPU。
